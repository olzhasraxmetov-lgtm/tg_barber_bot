# Чистая архитектура: домен не знает о Telegram и базе

Проект делится на слои с зависимостями строго внутрь: `domain` (сущности и правила — подсчёт свободных окон, правила отмены/переноса, без внешних библиотек) → `application` (use cases и порты-интерфейсы: репозитории, часы, отправка уведомлений) → `infrastructure` (SQLAlchemy/SQLite, Alembic, реализация уведомлений через Telegram) и `presentation` (aiogram + aiogram-dialog handlers, которые только вызывают use cases). Сборка зависимостей — в одной точке входа. Выбрано ради тестируемости доменной логики без Telegram и БД и как демонстрация архитектуры в портфолио; цена — больше файлов и маппинг между ORM-моделями и доменными сущностями.

## Consequences

- Текущее время приходит в домен через порт часов, а не `datetime.now()` — иначе правила «3 часа» и «24 часа» не протестировать.
- ORM-модели живут только в `infrastructure`; домен оперирует своими dataclass-сущностями.
- aiogram-dialog и FSM — деталь `presentation`; use cases не знают о диалогах и кнопках.
