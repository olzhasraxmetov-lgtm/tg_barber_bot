# SQLite и защита от двойной записи через занятые шаги сетки

Бот обслуживает одного мастера одним процессом (long polling), поэтому храним данные в SQLite (WAL) через SQLAlchemy 2 async + aiosqlite, а не в PostgreSQL: меньше эксплуатации, бэкап — копия файла. Двойную запись исключаем не проверкой в коде, а схемой: каждая запись занимает строки по 30 минут в таблице занятых шагов сетки с `UNIQUE` по времени начала; конфликт вставки = «окно уже занято». Это стандартный SQL и переносится на Postgres без изменений.

## Consequences

- Длительность услуги обязана быть кратной 30 минутам (см. `CONTEXT.md`, «Услуга»).
- Нужен хостинг с постоянным диском и ежедневный бэкап файла БД.
- Переход на Postgres оправдан, если появятся несколько процессов-писателей (несколько мастеров, отдельная веб-админка) или хостинг без постоянного диска.
